---
title: Builtin Implement Blocks
description: Adding methods to builtin scalars, slices, many pointers and array shapes.
---

A builtin type takes methods through an `implement builtin` block. The block target names the type or the container shape:

```zn
implement builtin i32 {
  pub fn is_even(*const self) bool {
    return (*self) % 2 == 0;
  }
}

fn main() {
  const n: i32 = 4;

  @println("{}", n.is_even());
}
```

The target is one of the integer types, `f32`, `f64`, `bool` or `char`. `void` and `never` are rejected, and so is any user type name: use an ordinary `implement` block for those.

## Receivers

The receiver works like a struct method. It is the first parameter when that parameter has no name:

| Receiver | Mode |
|----------|------|
| `self` | owned value |
| `const self` | owned, read only |
| `*self` | mutable borrow |
| `*const self` | read only borrow |

```zn
implement builtin i32 {
  fn by_value(self) i32 {
    return self + 1;
  }

  fn by_const_value(const self) i32 {
    return self + 2;
  }

  fn by_mut_ref(*self) i32 {
    *self += 3;
    return *self;
  }

  fn by_const_ref(*const self) i32 {
    return (*self) + 4;
  }
}

fn main() {
  let a: i32 = 10;

  @println("{} {}", a.by_value(), a.by_const_value());
  @println("{} {}", a.by_mut_ref(), a);

  const p: *i32 = &a;

  @println("{}", p.by_const_ref());
}
```

A method is reachable through a value and through a pointer to it. The compiler derefs the receiver, so `p.by_const_ref()` calls the `*const self` method on the pointee. A method that takes `*self` cannot be called through a `*const` pointer, and a value receiver gets a copy.

Inside a pointer receiver the value is read through `(*self)`, because `self` holds the address, not the number.

## Static methods

A parameter with a name is an ordinary argument, so a method without `self` is static and is called on the type name:

```zn
implement builtin i32 {
  fn largest() i32 {
    return 2147483647;
  }

  fn smallest() Self {
    return -2147483647 - 1;
  }

  fn is_extreme(value: i32) bool {
    return value == Self.largest() || value == Self.smallest();
  }
}

fn main() {
  @println("{} {}", i32.largest(), i32.smallest());
  @println("{} {}", i32.is_extreme(2147483647), i32.is_extreme(0));
}
```

Calling a static method on a value is `zeen::typechecker::static_method_on_instance`, with a help that points to `Type.method(...)`.

`Self` is the target type. It works in the return type, in annotations and as a name for static calls inside the block. A bare `Self` without a call or a type position is `zeen::typechecker::type_name_as_value`.

## Methods with generics

A method can declare its own generics like a struct method:

```zn
implement builtin i32 {
  fn pick[T](first: T, second: T) T {
    return first;
  }
}

fn main() {
  @println("{} {}", i32.pick(42, 7), i32.pick(true, false));
}
```

## Container targets

Slices, many pointers and fixed-size arrays take methods through the same kind of block. When the target mentions a parameter, the block header declares it:

```zn
implement builtin [4]u8 {
  fn total(*const self) u32 {
    return @as(u32, (*self)[0]) + @as(u32, (*self)[1]) + @as(u32, (*self)[2]) + @as(u32, (*self)[3]);
  }
}

implement[T] builtin []T {
  fn first_or(*const self, fallback: T) T {
    if ((*self).len == 0) {
      return fallback;
    };

    return (*self)[0];
  }
}

implement[T] builtin [*]T {
  fn head(*const self) T {
    return (*self)[0];
  }
}

fn main() {
  const bytes: [4]u8 = {1, 2, 3, 4};
  const numbers: [3]i32 = {7, 8, 9};

  @println("{}", bytes.total());
  @println("{}", numbers[..].first_or(0));
  @println("{}", (@as([*]i32, &numbers[0])).head());
}
```

The accepted shapes are `[]T`, `[]const T`, `[*]T`, `[*]const T` and arrays with a literal length such as `[4]u8` or `[4]T`. `const` is part of the shape: a block on `[]T` does not match a `[]const T` receiver, and a block on `[]const T` does not match `[]T`. Declare both when both should work.

The array length is an integer literal above zero. `[0]u8` and `[1 + 1]u8` are rejected, and a length parameter is not supported, so a generic array keeps its concrete length.

A pointer target such as `implement builtin *i32` is rejected too. Pointer transparency already lets a value method be called through `*i32` and `*const i32`.

## Overloads

Blocks rank the same way as ordinary `implement` blocks:

1. a block specialized on the exact concrete target,
2. a block whose bounds hold,
3. a block without bounds,
4. a block whose bounds fail.

```zn
implement[T] builtin []T {
  fn kind(*const self) i32 {
    return 1;
  }
}

implement[T: Copy] builtin []T {
  fn kind(*const self) i32 {
    return 2;
  }
}

implement builtin [4]u8 {
  fn label(*const self) i32 {
    return 3;
  }
}

implement[T] builtin [4]T {
  fn label(*const self) i32 {
    return 1;
  }
}

struct Payload {
  pub x: i32,
}

fn main() {
  let numbers: [4]i32 = {7, 8, 9, 10};
  let bytes: [4]u8 = {1, 2, 3, 4};
  let owned = {Payload { .x = 5 }};

  @println("{}", numbers[..].kind());
  @println("{}", owned[..].kind());
  @println("{} {}", bytes.label(), numbers.label());
}
```

`i32` is `Copy` and `Payload` is not, so `numbers[..]` uses the bounded `kind` and `owned[..]` falls back to the unbounded one. `[4]u8` matches its own exact block while `[4]i32` uses the generic one.

The same name on two different targets is allowed, since the target is part of the symbol. The same name with the same signature twice on one target is `zeen::typechecker::duplicate_method`.

## Visibility

A method is visible inside the module that declares it. `pub` makes it callable from other modules. The rest of the visibility rules match ordinary items.

An own method wins over a builtin interface method with the same name. A block may declare `hash` on `i32` and `n.hash()` then calls that method instead of the builtin `Hash::hash`.

## Interfaces

A builtin target implements a user interface through `implement Interface : builtin Target`:

```zn
interface Show {
  pub fn show(*const self) []const char;
}

implement Show : builtin i32 {
  fn show(*const self) []const char {
    return "i32";
  }
}

fn main() {
  const n: i32 = 5;

  @println("{}", n.show());
}
```

The target grammar is the same as in an `implement builtin` block, and an empty interface block picks up a matching inherent method from one. [User Interfaces](/ownership-types/user-interfaces/) covers bounds, static interface methods and the `duplicate_impl` rule.

Core interfaces such as `Add`, `Eq` or `Hash` are already provided for builtin types, so `implement Add : builtin i32` reports `zeen::typechecker::core_interface_impl`.
