---
title: Builtin Implement Blocks
description: Adding methods to builtin scalars, slices, many pointers and array shapes.
---

A builtin type takes methods through an `implement builtin` block. The same method syntax works as on a struct, and the target names the builtin type or the container shape.

## Targets

```zn
implement builtin i32 {
  pub fn is_even(*const self) bool {
    return (*self) % 2 == 0;
  }
}

fn main() {
  const n: i32 = 4;

  @println("{}", n.is_even());
}
```

A scalar target is one of the integer types, `f32`, `f64`, `bool` or `char`. `void` and `never` are refused with ``not supported: `void` and `never` cannot have builtin implement blocks``, and a user type name in that position is a syntax error that asks for the block's generic parameters. A user type gets an ordinary `implement` block instead.

## Receivers

The receiver is the first parameter when it has no name:

| Receiver | Mode |
|----------|------|
| `self` | owned value |
| `const self` | owned, read only |
| `*self` | mutable borrow |
| `*const self` | read only borrow |

```zn
implement builtin i32 {
  fn by_value(self) i32 {
    return self + 1;
  }

  fn by_const_value(const self) i32 {
    return self + 2;
  }

  fn by_mut_ref(*self) i32 {
    *self += 3;
    return *self;
  }

  fn by_const_ref(*const self) i32 {
    return (*self) + 4;
  }
}

fn main() {
  let a: i32 = 10;

  @println("{} {}", a.by_value(), a.by_const_value());

  @println("{} {}", a.by_mut_ref(), a);

  const p: *i32 = &a;

  @println("{}", p.by_const_ref());
}
```

```text
11 12
13 13
17
```

A value receiver gets a copy, while `*self` writes through to the binding. Method calls see through a pointer, so `p.by_const_ref()` reaches the `*const self` method on the pointee without a manual deref. A `*const` pointer cannot call a `*self` method, because that would write through a read-only view, and the compiler reports `zeen::typechecker::assign_to_const`.

Inside a pointer receiver the value is read through `(*self)`, since `self` holds the address.

## Static methods

A named first parameter is an ordinary argument, so a method without `self` is static and is called on the type name:

```zn
implement builtin i32 {
  fn largest() i32 {
    return 2147483647;
  }

  fn smallest() Self {
    return -2147483647 - 1;
  }

  fn is_extreme(value: i32) bool {
    return value == Self.largest() || value == Self.smallest();
  }
}

fn main() {
  @println("{} {}", i32.largest(), i32.smallest());
  @println("{} {}", i32.is_extreme(2147483647), i32.is_extreme(0));
}
```

Calling one on a value reports `zeen::typechecker::static_method_on_instance` with the help `use `Type.method(...)` to call a static method`. `Self` is the target type and works in return types, annotations and static calls inside the block. A bare `Self` in a value position is `zeen::typechecker::type_name_as_value`, because a type name has no value.

## Method generics

A method declares its own generics like a struct method:

```zn
implement builtin i32 {
  fn pick[T](first: T, second: T) T {
    return first;
  }
}

fn main() {
  @println("{} {}", i32.pick(42, 7), i32.pick(true, false));
}
```

## Containers

Slices, many pointers and fixed arrays take methods through the same block. A shape that mentions a parameter declares it in the block header:

```zn
implement builtin [4]u8 {
  fn total(*const self) u32 {
    return @as(u32, (*self)[0]) + @as(u32, (*self)[1]) + @as(u32, (*self)[2]) + @as(u32, (*self)[3]);
  }
}

implement[T] builtin []T {
  fn first_or(*const self, fallback: T) T {
    if ((*self).len == 0) {
      return fallback;
    };

    return (*self)[0];
  }
}

implement[T] builtin [*]T {
  fn head(*const self) T {
    return (*self)[0];
  }
}

fn main() {
  const bytes: [4]u8 = {1, 2, 3, 4};
  const numbers: [3]i32 = {7, 8, 9};

  @println("{}", bytes.total());
  @println("{}", numbers[..].first_or(0));
  @println("{}", (@as([*]i32, &numbers[0])).head());
}
```

The accepted shapes are `[]T`, `[]const T`, `[*]T`, `[*]const T` and an array with a positive literal length such as `[4]u8` or `[4]T`. Elements may themselves be shapes, so `[][3]T` and `[2][3]T` are valid targets. `const` is part of the shape: a block on `[]const T` does not match a `[]T` receiver, and the call reports the method as missing.

The length has to be an integer literal above zero. `[0]u8`, `[1 + 1]u8` and a length parameter `[N]u8` all report a parser error that asks for a literal length, so a generic array keeps its concrete length. A pointer target such as `implement builtin *i32` is rejected too, since pointer transparency already lets a value method be called through `*i32`.

## Overloads

Blocks rank the same way as ordinary `implement` blocks:

1. a block specialized on the exact concrete target,
2. a block whose bounds hold,
3. a block without bounds,
4. a block whose bounds fail.

```zn
implement[T] builtin []T {
  fn kind(*const self) i32 {
    return 1;
  }
}

implement[T: Copy] builtin []T {
  fn kind(*const self) i32 {
    return 2;
  }
}

implement builtin [4]u8 {
  fn label(*const self) i32 {
    return 3;
  }
}

implement[T] builtin [4]T {
  fn label(*const self) i32 {
    return 1;
  }
}

struct Payload {
  pub x: i32,
}

fn main() {
  let numbers: [4]i32 = {7, 8, 9, 10};
  let bytes: [4]u8 = {1, 2, 3, 4};
  let owned = {Payload { .x = 5 }};

  @println("{}", numbers[..].kind());
  @println("{}", owned[..].kind());
  @println("{} {}", bytes.label(), numbers.label());
}
```

```text
2 1
3 1
```

`i32` is `Copy`, so `numbers[..]` takes the bounded block, while `Payload` falls back to the unbounded one. `[4]u8` matches its exact block and `[4]i32` uses the generic one.

The same name on two targets is allowed, because the target belongs to the symbol. The same name with the same signature twice on one target reports `zeen::typechecker::duplicate_method`.

## Visibility

A method is visible in the module that declares it, and `pub` opens it to other modules. The rest matches ordinary items.

An own method wins over a core interface method with the same name. A block that declares `hash` on `i32` makes `n.hash()` call it instead of `Hash::hash`.

## Interfaces

A builtin target implements a user interface through `implement Interface : builtin Target`. The target grammar matches the inherent block:

```zn
interface Show {
  pub fn show(*const self) []const char;
}

implement Show : builtin i32 {
  fn show(*const self) []const char {
    return "i32";
  }
}

fn main() {
  const n: i32 = 5;

  @println("{}", n.show());
}
```

An empty interface block picks up a matching method from an inherent `implement builtin` block. [Interfaces](/functions-closures/interfaces/) covers bounds, associated types and the `duplicate_impl` rule. Core interfaces such as `Add`, `Eq` and `Hash` already come with every builtin type, so `implement Add : builtin i32` reports `zeen::typechecker::core_interface_impl`.
