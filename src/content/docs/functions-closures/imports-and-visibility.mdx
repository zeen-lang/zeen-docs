Modules are `.zn` files. `use` loads another module and brings its `pub` items into the current module unqualified. The project root is the directory of the entry file.

<FileTree>

- main.zn entry file, its directory is the project root
- utils/
  - helpers.zn

</FileTree>

`utils/helpers.zn`:

```zn
pub fn double(x: i32) i32 {
  return x * 2;
}
```

`main.zn`:

```zn
use utils.helpers;

fn main() {
  @println("{}", double(2));
}
```

An import does not create a namespace. `helpers.double` is not valid, `double` is called directly.

## Core

Core modules are implicit, so `Option`, `Result`, `Copy`, `Drop`, `Display`, `Debug` and `Iterator` need no import. Core names are reserved: declaring `struct Option` reports `zeen::resolver::core_reserved`.

## Use paths

Dots map to directories, and the last segment maps to a `.zn` file:

```zn
use std.string;
use std.c.posix.pthread;
```

The first segment picks the base:

| Path | Base |
|---|---|
| no prefix | directory of the current file |
| `root` | project root |
| `super` | parent directory of the current file |
| `std` | std root |
| package name | directory from `--pkg NAME=PATH` |

```zn
use utils.helpers;
use root.utils.helpers;
use super.helpers;
use std.string;
```

A bare module name falls back to `name/index.zn` when `name.zn` does not exist. `use utils;` and `use utils.index;` load the same file.

Packages connect a name to a directory on the command line:

```sh
zeen main.zn output --pkg mathpkg=tools/math
```

`use mathpkg.lib;` then loads `tools/math/lib.zn`, and diagnostics show the module as `mathpkg.lib`.

The std root comes from `--std`, then `ZEEN_STD`, then `~/.zeen/std`, then `share/zeen/std` next to the compiler. A missing std root reports `zeen::resolver::std_not_configured`.

## Prelude

Some std modules load on their own when a program needs them. Mentioning `String` or `List` injects `std.string` or `std.collections.list`, `@format` injects `std.string`, and a fat closure pulls in `std.fn`. The prelude is usage driven, so a program that uses none of them needs no std root.

## Visibility

Items are private by default. `pub` opens a function, struct, enum, alias, constant, global, field or method to other modules:

```zn
pub fn triangulate() {
  @println("triangulating");
}
```

Imports are private too. A module keeps the names it imported, and an importer does not see them. `pub use` re-exports an import:

```zn
pub use leaf;
```

With `pub use leaf;` inside `chain/mid.zn`, a module that imports `chain.mid` can call the public items of `chain.leaf`. Without `pub`, those names stay inside `mid`.

A local declaration wins over an imported name. Two modules may also declare the same private name, and importing both is fine.

## Errors

| Situation | Code |
|---|---|
| module not found | `zeen::resolver::include_error` |
| private item used from another module | `zeen::resolver::private_item` |
| one public name from two imported modules | `zeen::resolver::ambiguous_import` |
| duplicate declaration in one module | `zeen::resolver::duplicate_definition` |
| core name redeclared | `zeen::resolver::core_reserved` |

When several modules define `main`, the entry point comes from the root module.
