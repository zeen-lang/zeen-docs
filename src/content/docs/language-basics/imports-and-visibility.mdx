`use` loads another module and brings its `pub` items into the current module. The items join the local namespace unqualified, so a function is called by its own name and there is no `helpers.double` form.

The project root is the directory of the entry file. A module reached through the root can import its neighbours by path:

<FileTree>

- main.zn entry file, its directory is the project root
- utils/
  - helpers.zn

</FileTree>

`utils/helpers.zn`:

```zn
pub fn double(x: i32) i32 {
  return x * 2;
}
```

`main.zn`:

```zn
use utils.helpers;

fn main() {
  @println("{}", double(2));
}
```

## What needs no import

Three groups of names are already in scope in every module.

Core modules are implicit. `Option`, `Result`, `Copy`, `Drop`, `Display`, `Debug`, `Iterator` and the rest of `lib/core` need no `use`. Core names are reserved: declaring `struct Option` reports `zeen::resolver::core_reserved`.

Compiler macros are not library functions. `@println`, `@format`, `@as`, `@sizeof` and the others are built into the compiler, so no import can provide or replace them.

The std prelude is injected by usage. A module that mentions `String` gets `std.string`, one that mentions `List` gets `std.collections.list`, `@format` pulls in `std.string` and a fat closure pulls in `std.fn`. The compiler looks at the names a module uses and adds the `use` lines itself. A program that uses none of these still builds on a machine without std.

Everything else needs an explicit `use`, including most of std: `use std.fs;` for files, `use std.json;` for JSON, `use std.collections.map;` for `HashMap`.

## Use paths

Dots map to directories, and the last segment maps to a `.zn` file:

```zn
use std.string;
use std.c.posix.pthread;
```

The first segment picks the base:

| Path | Base |
|---|---|
| no prefix | directory of the current file |
| `root` | project root |
| `super` | parent directory of the current file |
| `std` | std root |
| package name | directory from `--pkg NAME=PATH` |

```zn
use utils.helpers;
use root.utils.helpers;
use super.helpers;
use std.string;
```

A bare module name falls back to `name/index.zn` when `name.zn` does not exist. `use utils;` and `use utils.index;` load the same file. Imports are not transitive: a module that needs `std.string` writes the line itself, even when the module it imports already has it.

Packages connect a name to a directory on the command line:

```sh
zeen main.zn output --pkg mathpkg=tools/math
```

`use mathpkg.lib;` then loads `tools/math/lib.zn`, and diagnostics show the module as `mathpkg.lib`. [Package Manager](/toolchain/package-manager/) generates these arguments from `Zora.toml`.

The std root comes from `--std`, then `ZEEN_STD`, then `~/.zeen/std`, then `share/zeen/std` next to the compiler. A missing std root reports `zeen::resolver::std_not_configured`.

## Visibility

Items are private by default. `pub` opens a function, struct, enum, alias, constant, global, field or method to other modules:

```zn
pub fn triangulate() {
  @println("triangulating");
}
```

A struct field or method needs its own `pub`. A public struct with a private field still hides that field, and `main` in another module cannot reach it even when the type is public.

Imports are private. A module keeps the names it imported, and an importer does not see them. `pub use` re-exports an import:

```zn
pub use leaf;
```

With `pub use leaf;` inside `chain/mid.zn`, a module that imports `chain.mid` can call the public items of `chain.leaf`. Without `pub`, those names stay inside `mid`.

A local declaration wins over an imported name. Two modules may declare the same private name, and importing both is fine until one of those names is used.

## Errors

| Situation | Code |
|---|---|
| module not found | `zeen::resolver::include_error` |
| private item used from another module | `zeen::resolver::private_item` |
| one public name from two imported modules | `zeen::resolver::ambiguous_import` |
| duplicate declaration in one module | `zeen::resolver::duplicate_definition` |
| core name redeclared | `zeen::resolver::core_reserved` |

When several modules define `main`, the entry point comes from the root module. [Modules](/language-basics/zeen-modules/) covers the file-to-module mapping.
