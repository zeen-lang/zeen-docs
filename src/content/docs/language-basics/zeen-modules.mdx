---
title: Modules
description: A source file is a module, and the entry file is the root.
---

A module is one `.zn` file. There is no `module` keyword and nothing to declare inside the file: the file name is the module name, without the extension. A file at `utils/helpers.zn` is the module `utils.helpers` for anyone who imports it.

The file passed to the compiler is the root module, and its directory becomes the project root, the base for every relative `use` path. When several modules define `main`, the compiler takes it from the root module.

## What a module holds

A module holds declarations: functions, structs, enums, aliases, constants, globals, interfaces and `implement` blocks. Declarations hold statements, and statements hold expressions.

```zn
fn main() {
  const calculation = 2 + 2 * 2;

  @println("Result: {}", calculation);
}
```

`fn main` is a declaration, `const calculation = ...` is a statement and `2 + 2 * 2` is an expression. The same shapes appear in every module, whether it runs or only provides functions for others.

## Directories as modules

A directory can stand for its own module. `use utils;` loads `utils/index.zn` when no `utils.zn` file exists, so a folder with an `index.zn` behaves like a single module with the folder's name. `use utils.index;` reaches the same file.

## Reachability

The compiler reads the root module and follows `use` declarations from there. A `.zn` file that nothing imports is never parsed, so leaving a draft module in the tree costs nothing until an import mentions it.
