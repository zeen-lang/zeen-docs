title: Linking
description: The C toolchain the compiler needs, the link flags, and how to read a link error.

Code generation stops at an object file. The compiler does not link it by itself: it finds a C toolchain and passes the object along. A missing toolchain or a missing native library fails at that step, not in the compiler.

## Toolchain by target

Candidates are tried in order, and the first one on `PATH` wins.

| Target | Candidates |
|---|---|
| Linux gnu | `<triple>-gcc`, then `cc`, `gcc`, `clang` |
| Linux musl | `x86_64-linux-musl-gcc`, `musl-gcc`; links statically |
| Windows gnu | `<arch>-w64-mingw32-gcc`, then `gcc`, `cc` |
| Windows msvc | `link.exe` with the Windows SDK, Windows only |
| wasm | `wasm-ld`, undefined symbols become imports |
| Android | the NDK at `ANDROID_NDK_HOME` or `ANDROID_NDK_ROOT` |
| anything else | `cc`, `gcc`, `clang` |

A gnu target looks for its distribution alias first, because a plain `gcc` does not always find the system libraries on a cross setup. When no local candidate exists, the compiler falls back to `clang -target <triple>`.

## Flags

| Flag | Effect |
|---|---|
| `--linker-path <PROGRAM>` | use this linker instead of the detected one |
| `--link <LIB>` | append `-l<LIB>`, or `<LIB>.lib` for MSVC |
| `--link-dir <PATH>` | append `-L<PATH>`, or `/LIBPATH:<PATH>` for MSVC |
| `extern link "<file>"` | compile a C source file and append it to the link |

The three flags describe the machine, so they belong to the build command. `extern link` sits in the source, so the C file travels with the program. [Extern](/functions-closures/extern/) shows it with a C helper.

## Link errors

The report carries no `zeen::` code, only `[Error]: Linker failed` and the linker's own message.

| Message | Fix |
|---|---|
| `failed to spawn linker ... No such file or directory` | install a C toolchain, or point `--linker-path` at one |
| `MSVC target ... requires MSVC tools and the Windows SDK` | install MinGW-w64 and build with `--target x86_64-pc-windows-gnu` |
| `__atomic_fetch_add_8` undefined | the compiler retries once with `-latomic`; if that retry fails, install `libatomic` |
| undefined reference from an `extern fn` call | `--link <LIB>`, plus `--link-dir <PATH>` when the library lives outside the default paths |

## Output suffix

| Target | Binary | Object |
|---|---|---|
| Windows | `.exe` | `.obj` |
| wasm | `.wasm` | `.o` |
| Linux, macOS | none | `.o` |
